# 公开 Issue / 缺陷单转换说明

仅在提交 GitHub issue、缺陷单或研发交接材料时读取。以最终 Markdown 报告为事实来源，不再重新编写一套调查报告。

## 转换步骤

1. 从最终报告提取一句话摘要、影响范围、失败率、首次异常版本和已知正常基线。
2. 附上 `collect_env.py` 输出，并补齐 vLLM/vLLM Ascend commit、镜像 digest、CANN、driver/firmware、PyTorch、`torch_npu`、NPU 拓扑和模型/量化 revision。
3. 提供可复制的最小启动命令、请求或评测命令、期望/实际结果、首差异 token/step 和必要日志。
4. 保留最小消融表，明确唯一变化、样本数、失败数/分数及 A/B/A 结果；区分事实、假设、规避和根因修复。
5. 用有限请求数、超时和停止条件写复现步骤，不提供无限压力循环。

## 公开前检查

- 删除密码、token、私钥、内网地址、用户数据和受限模型内容；命令与环境变量必须脱敏。
- 长日志、逐样本数据和大文件使用附件，只在正文放关键片段；不要只提供截图。
- 写明可用规避方案及性能代价，但不把“关闭后不复现”描述为根因确认。
- 确认外部维护者无需内部上下文即可复现；无法公开的材料改为内部缺陷单附件。
