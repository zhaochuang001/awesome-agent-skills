# npu-migrate 行为契约

本文件是迁移决策与安全边界的判定依据。机器清单与空闲状态的语义以 server-management skill 的契约为准。

## 状态词汇

| 状态 | 含义 |
| --- | --- |
| `migrated` | 迁移完成且目标容器 running（启动脚本进程已执行） |
| `needs_input` | 缺少必要输入：卡数提取不到且未给 `--npus`；目标机空闲卡不足；无满足条件的机器 |
| `blocked` | 前置条件不满足：源机不在清单/不可达；源容器不存在 |
| `failed` | 执行阶段失败：commit/传输/同步/起容器/启动脚本 |

## 选机策略

- 数据源：fleet 服务在跑时用 `/api/servers`；否则对清单内全部启用机器并行探测（`probe_remote_npu`）
- 空闲卡定义与 server-management 一致：health OK 且 AICore ≤5% 且 HBM ≤5%
- 过滤：可达、非源机、空闲卡数 ≥ 需求
- 自动选择：空闲卡最多的机器（对用户最保险，留有余量）
- 用户指定目标（--target）：校验空闲充足性，不足时返回 needs_input 并附备选列表，不擅自换机器

## 卡分配与设备重映射

- 目标机空闲卡升序取前 N 张
- `docker run --device /dev/davinci<物理卡号>` 逐卡挂载
- 容器内可见编号重排为 `0..N-1`，写入 `ASCEND_RT_VISIBLE_DEVICES`（源容器的该变量被替换，其余环境变量原样保留）
- 共享设备（`davinci_manager`、`hisi_hdc*`、`devmm_svm`）从源容器原样复刻

## 传输策略

- 镜像：源机 `docker save | gzip -1 | ssh 目标 'gzip -d | docker load'`（gzip -1 换速度，镜像常为多 GB）；超时上限 1 小时
- 代码：rsync 增量同步（服务器上有 rsync 时）；无 rsync 降级 tar 管道
- 代码同步到**相同绝对路径**，使容器挂载参数无需修改
- 任何传输都不经过本地 Windows（用户已确认服务器间可直连）

## 复刻规则（docker run 参数）

| 参数 | 处理 |
| --- | --- |
| 镜像 | 迁移镜像 `migrate/<容器名>:<时间戳>` |
| `--name` | 与源容器同名（不同机器不冲突） |
| `--restart` / `--privileged` / `--network` | 原样复刻 |
| `--device` | 数字卡重映射，共享设备原样 |
| `-e` | `ASCEND*_VISIBLE_DEVICES` 重排替换，其余原样 |
| `-v` | 原样复刻（代码已同步到相同路径） |
| `-p` | 原样复刻，冲突即失败 |

## 失败与回滚

- 任何步骤失败：源容器不动、源机 commit 产物镜像保留；报告给出错误与修复提示后可整体重跑（幂等）
- 目标机起容器失败：`docker rm -f` 清理半成品容器（镜像保留供重试）
- 回滚 = 回源机重启服务（源容器一直保留）

## agent 使用规则

- 用户首次迁移某个容器时，先建议 `--plan` 干跑看方案（特别是卡映射与外部挂载列表）
- 拿到 `needs_input` 时把备选机器列表呈现给用户再决策，不要自行选一台替代用户指定的机器
- 迁移成功后提醒用户：外部挂载未同步项、源容器清理命令（`docker rmi`）、确认稳定后才建议 `--stop-source` 重跑或手动停源
- 不主动替用户决定停源容器；这是用户确认过新服务稳定后才做的事

## 触发示例

应触发：

- "80.5.17.119 的卡被占了，帮我把容器迁到别的机器"
- "把 xxx 容器和 /home/user/code 搬到有空卡的机器上，启动脚本是 /workspace/start.sh"
- "迁移服务到 141.61.81.23"

不应触发：

- "同步代码到远程"（无容器迁移诉求时，普通同步）
- "在 80.5.9.126 上起个新服务"（非迁移，是部署）
